# Split AppHeader and retune its timing

Status: ready-for-agent
Progress: resolved

## Problem

`src/common/components/layout/app-header.tsx` (about 300 lines) holds the
scroll state, the mobile drawer's open and render state, route-change closing,
and the header styling in one component. It is hard to follow and to change
safely.

Its timing values were chosen ad hoc: the scroll handler's debounce, the 50ms
delay before the drawer unmounts, and the drawer's transition. Nobody has
checked that they feel right together.

Triage found that the 50ms unmount cuts off vaul's 500ms close animation, so
the drawer vanishes instead of sliding out. The delay was 500ms when the header
was built and was cut to 50ms in an unrelated commit with no reason given.

## Done when

- The drawer's mount and unmount is left to vaul. The header keeps no render
  flag, next-frame open, or unmount timer of its own, and the drawer slides out
  fully before its content leaves the DOM.
- The "scrolled" state comes from an `IntersectionObserver` on a marker at the
  top of the page (16px threshold), not a debounced scroll listener, so the
  header border updates while scrolling.
- The header's style depends only on the scrolled state. It no longer hides
  its border while the drawer is open.
- Scroll tracking and hero-in-view tracking are their own hooks, the mobile
  drawer is its own component that owns its open state and route-change
  closing, and `AppHeader` composes them.
- Behavior is otherwise unchanged: focus moves into the drawer on open, the
  drawer closes on route change and on link tap, and the wordmark still hides
  while the home hero heading is in view.

Changed during triage from "named timing constants that agree": removing the
manual drawer lifecycle and the debounce leaves no ad hoc timing values to name.

## Agent Brief

**Category:** enhancement
**Summary:** Split `AppHeader` into composable hooks and a mobile nav component, and fix the drawer's cut-off close animation

**Current behavior:**
`AppHeader` is one large client component. It tracks scroll with a scroll
listener debounced by 100ms, so the "scrolled" border only changes after
scrolling pauses. It wraps vaul's `Drawer` in a hand-rolled lifecycle (a
`shouldRenderDrawer` flag, a `requestAnimationFrame` before opening, and a 50ms
`setTimeout` before unmounting). vaul's close animation is 500ms, so the drawer
content is removed mid-animation and vanishes instead of sliding out. The header
also has a three-state `HeaderState` (`drawerOpen` / `closedScrolled` /
`closedNotScrolled`) that hides the bottom border while the drawer is mounted.
`useHeroInView` already exists but lives inside the header module.

**Desired behavior:**

- The mobile drawer is a standalone component that owns its own `open` state,
  passes it straight to vaul's `Drawer` (`open` / `onOpenChange`), and lets vaul
  mount and unmount the content. It closes itself when the pathname changes,
  and when any of its links is tapped (so same-page links like `/#contact`
  still close it). Focus still moves into the drawer when it opens.
- A `useIsScrolled`-style hook reports whether the page has scrolled past
  16px, using an `IntersectionObserver` on a marker element at the top of the
  page, the same pattern as `useHeroInView`. No scroll listener, no timer.
- `useHeroInView` moves into its own hook module unchanged in behavior.
- The header's border depends only on the scrolled state: shown when
  scrolled, transparent otherwise. The three-state `HeaderState` becomes a
  boolean.
- The nav item list and the `isCurrent(pathname, href)` check are shared by
  the desktop nav and the mobile drawer from one place.
- `AppHeader` composes the hooks, the wordmark, the desktop nav, the theme
  toggle, and the mobile nav component.

**Key interfaces:**

- `AppHeader()`: same export and rendered output, minus the drawer lifecycle
  and scroll logic, plus a hidden 16px marker `<div>` rendered before
  `<header>`. The marker is pinned to the top of `<body>`, which must stay
  `relative`. Changed during implementation: the observer needs an element at
  the top of the page, and the header owns it.
- `useIsScrolled(scrollThresholdRef: RefObject<HTMLElement | null>): boolean`:
  true once the page has scrolled past the marker. Changed during
  implementation from `useIsScrolled(): boolean`: passing the marker as a ref
  avoids a second DOM id that the header and the hook would both have to agree
  on.
- `useHeroInView(pathname: string): boolean`: unchanged signature and behavior.
- Mobile nav component: no props required. It reads the pathname itself.
- Nav items: `{ href: string; label: string }[]` plus
  `isCurrent(pathname: string, href: string): boolean`, shared by both navs.

**Acceptance criteria:**

- [ ] No `setTimeout`, `requestAnimationFrame`, render flag, or scroll event
      listener remains in the header or its hooks.
- [ ] At mobile width in the running app, closing the drawer (backdrop tap,
      link tap, or navigation) plays the full slide-out before the content
      disappears.
- [ ] Opening the drawer moves focus into it.
- [ ] Navigating via a drawer link closes the drawer, and tapping the link
      for the current page also closes it.
- [ ] The header bottom border appears while still scrolling, once the page
      is past 16px, and disappears when back at the top.
- [ ] On the home page the header wordmark is still hidden while the hero
      heading is in view and shown after it scrolls away.
- [ ] Desktop nav markup, `aria-current`, and styling are unchanged.
- [ ] `pnpm static-analysis` and `pnpm test` pass.

**Out of scope:**

- Changing CSS transition durations (header 200ms, wordmark 300ms) or any
  subjective feel tuning.
- Adding a DOM test environment or component tests.
- Changing the `Drawer` UI primitive or upgrading vaul.
- Any visual redesign of the header or drawer.
